# Components — Overview

## Concept {#concept}

Each note in this folder is a **contract**: what the component takes, what state and slots it hands to the skin's renderer, which tokens a skin should use, and what accessibility it guarantees under *every* skin. Platform notes implement the contract. Skins draw it.

### The v1 set

v1 has 40 component notes (ADR-21, plus CamoPagedList and CamoSkeleton from ADR-29, and the date and time pickers, stepper and accordion from ADR-35), covering roughly 75–85% of each major design system ([Component Inventory](/guide/foundations/component-inventory)).

Overlays (dialogs, bottom sheets) open through the **platform's navigator**: Flutter `showCamoDialog`/`showCamoBottomSheet`, Compose Navigation 3 entries with Camouflage scene metadata. See [Overlays](/components/overlays/overlays).

### Reviewing a component: API or theme?

- **ADR-23:** a parameter goes into the component API only if every dialect can render it.
- **ADR-28:** a layout or proportion choice that a brand's Figma commonly changes goes into the component theme, with a per-skin default.
- **ADR-30:** for designs that go further (floating, hiding, expanding, reshaped components), offer the cheapest level that covers them: theme option → controlled behavior input → public building blocks → renderer override.

### About the "Material mapping preview" and defaults in component notes

Each component note shows a **Material mapping preview** and **Material defaults** in its component-theme table. Material is the *reference dialect* because its measurements are public and complete. **The v1 skin is Minimal**: its defaults for every component are in one table in [Minimal Skin](/guide/skins/minimal-skin) §3.4, and that's what v1 implements.

### Rules shared by every component

1. **Controlled.** The component never owns the source of truth. Values come in (`checked`, `value`) and changes go out (`onCheckedChange`, `onValueChange`). The only internal state is interaction (pressed/focused/hovered), which is visual.
2. **Camouflage's own vocabulary.** Components with visual variants take `appearance` (`Solid`, `Soft`, `Raised`, `Outline`, `Ghost`, `Link`) and `tone` (`Default`, `Error`, `Success`, `Warning`, `Info`), independently. They never use one design system's private terms (Material's `tonal`, Apple's `borderedProminent`). See [Design Language](/guide/foundations/design-language).
3. **The component owns behavior; the renderer owns visuals.** Callbacks, the semantics role and label, the enabled gate, the minimum touch target (48dp) and focusability are set by the component, so they hold under every skin.
4. **Layout stays with the platform.** No `CamoRow` or `CamoColumn`. Use `Row`/`Column`/`Box` (Compose) or `Row`/`Column`/`Stack` (Flutter), with `Camouflage.spacing` for gaps.
5. **Text is a value, icons are widgets, layout is a slot.** Labels, titles and messages are `String`s the renderer draws. Icons are passed as icon widgets (your `AppIcon.x()`) and follow the icon style the component sets. Nested actions are Camouflage components (dialog buttons, top-bar icon buttons). Only free layout (card, surface, dialog `content`) is a slot. See ADR-12 in [Decisions](/guide/project/decisions).
6. **Platform extras are added at the platform level.** Each platform adds its own conventional parameters (a Kotlin `modifier: Modifier`, a Flutter `key`) on top of the contract.

### How each component note is organised

- §1 Why: what problem the component solves.
- §2 Shape: the render flow for this component, and a Material mapping preview.
- §3 API: the **Contract** (parameters, state, slots), **Tokens used**, and **Accessibility**.
- §4 Build steps: the build checklist, ending in *Done when*.
- §5 Edge cases.

### The component skeleton {#kotlin-the-component-skeleton}

```kotlin
@Composable
public fun CamoButton(
    text: String,
    onClick: () -> Unit,
    modifier: Modifier = Modifier,                         // Compose convention: first optional param
    appearance: Appearance? = null,                         // null → ButtonTheme.defaultAppearance
    tone: Tone = Tone.Default,
    enabled: Boolean = true,
    loading: Boolean = false,
    prefixIcon: (@Composable () -> Unit)? = null,
    suffixIcon: (@Composable () -> Unit)? = null,
    interactionSource: MutableInteractionSource? = null,   // Compose convention: hoistable source
) {
    val skin = requireSkin("CamoButton")                                        // 1. fail fast, named
    val theme = requireTheme("CamoButton")
    val source = interactionSource ?: remember { MutableInteractionSource() }
    val interaction = source.collectInteractionState()                          // 2. pressed/focused/hovered
    val style = remember(skin, theme) { skin.button.defaults(theme).merge(theme.components.button) }   // 3. resolve
    val behavior = modifier                                                      // 4. behavior modifier
        .minimumTouchTarget()
        .clickable(source, indication = null, enabled = enabled, role = Role.Button, onClick = onClick)
        .semantics(mergeDescendants = true) { contentDescription = text }
    skin.button.Render(                                                          // 5. delegate
        state = ButtonState(text, enabled, loading, appearance ?: style.defaultAppearance, tone, interaction, source),
        slots = ButtonSlots(prefixIcon, suffixIcon),
        theme = theme, style = style, modifier = behavior,
    )
}
```

1. **Fail fast** with the component's name ([Provider and Scoping](/guide/architecture/provider-and-scoping#implementation)).
2. **Interaction**: `collectInteractionState()` (a core helper) combines `collectIsPressedAsState`, `collectIsFocusedAsState` and `collectIsHoveredAsState` into `InteractionState`.
3. **Resolve the component style** once per skin/theme change (`remember` keys).
4. **The behavior modifier** does clicks, the role, semantics and the touch target, with `indication = null` because the *renderer* draws the feedback.
5. **Delegate** to the renderer, which applies `behavior` outermost ([Skin Contract](/guide/architecture/skin-contract#implementation)).

### Core helpers every component uses {#kotlin-core-helpers-every-component-uses}

| Helper | What it does |
|---|---|
| `Modifier.minimumTouchTarget(size = 48.dp)` | a layout modifier that reports at least 48×48 and centers the visual content, expanding the pointer area without growing the visuals (the same technique as Material 3's `minimumInteractiveComponentSize`, reimplemented because core doesn't depend on material3) |
| `MutableInteractionSource.collectInteractionState()` | `InteractionState` from the four `collectIs…AsState` flows (pressed, focused, hovered, dragged) |
| `rememberRovingFocus(count)` | one Tab stop per group, arrow keys move (and select, for radios, segments, tabs, chip groups), RTL-aware |
| `Modifier.camoClickable(onClick, enabled, role)` | public: `clickable` + the **active skin's** feedback + the touch target, for an app's own clickable rows. Switching or borrowing skins restyles them too. |
| `rememberHideOnScroll(listState)` | `visible = false` while scrolling down, for the nav bar, top bar and FAB (ADR-30) |
| `ProvideContentStyle(color, iconStyle)` | sets `LocalCamoContentColor` + `LocalCamoIconStyle` for slots |
| `Modifier.camoError(message: String?)` | semantics `error(message)` + a polite live region when the message appears |

Every Flutter component note implements its base contract from Components — Overview using the same **component skeleton**. The Kotlin counterpart is Components — Overview, and comparing the two skeletons makes a good episode.

### The component skeleton {#dart-the-component-skeleton}

```dart
class CamoButton extends StatefulWidget {
  const CamoButton({
    super.key,
    required this.text,
    required this.onPressed,                    // VoidCallback?; null = disabled (Flutter convention, replaces base `enabled`)
    this.appearance,                            // null → CamoButtonTheme.defaultAppearance
    this.tone = Tone.defaultTone,
    this.loading = false,
    this.prefixIcon,
    this.suffixIcon,
    this.focusNode,                             // Flutter convention: hoistable focus node
  });
  // fields …
  @override
  State<CamoButton> createState() => _CamoButtonState();
}

class _CamoButtonState extends State<CamoButton> {
  bool get _enabled => widget.onPressed != null;
  late final _interaction = CamoInteractionController();              // 1. interaction state

  @override
  Widget build(BuildContext context) {
    final skin = Camouflage.skinOf(context, component: 'CamoButton'); // 2. fail fast, named
    final theme = Camouflage.themeOf(context, component: 'CamoButton');
    final style = skin.button.defaults(theme).merge(theme.components.button);   // 3. resolve
    final visual = skin.button.render(context,                         // 4. delegate
        ButtonState(text: widget.text, enabled: _enabled, loading: widget.loading, appearance: widget.appearance ?? style.defaultAppearance,
                    tone: widget.tone, interaction: _interaction.value, controller: _interaction),
        ButtonSlots(prefixIcon: widget.prefixIcon, suffixIcon: widget.suffixIcon), theme, style);
    return CamoBehavior(                                               // 5. behavior wraps the visual
      controller: _interaction, focusNode: widget.focusNode, enabled: _enabled,
      onActivate: widget.onPressed,
      semantics: (child) => Semantics(button: true, enabled: _enabled, label: widget.text,
                                      excludeSemantics: true, child: child),
      child: CamoTouchTarget(child: visual),
    );
  }

  @override
  void dispose() { _interaction.dispose(); super.dispose(); }
}
```

1. **Interaction** is owned by the component's `State` (`CamoInteractionController`), and listened to by renderers.
2. **Fail fast** with the component's name.
3. **Resolve** the component style.
4. **Delegate** to the renderer (a plain `Widget` comes back).
5. **Wrap** it in the behavior: focus, keyboard activation, hover, press positions, semantics, and the 48 × 48 touch target.

The `ListenableBuilder` around the renderer (so it rebuilds on interaction changes) lives inside `CamoBehavior`.

### Core helpers {#dart-core-helpers}

| Helper | What it does |
|---|---|
| `CamoBehavior` | `FocusableActionDetector` (focus, hover, Enter/Space → `ActivateIntent`) + `GestureDetector` (tap down/up/cancel with local positions → the controller) + semantics builder + `ListenableBuilder` |
| `CamoTouchTarget` | a `SingleChildRenderObjectWidget` that sizes itself to at least 48 × 48 and hit-tests the whole area, while painting the child at its own size (the same technique as Material's `_InputPadding`, reimplemented without Material) |
| `CamoContentStyle` | content color + icon style, plus `IconTheme` and `DefaultTextStyle` for native widgets |
| `CamoRovingFocus` | one Tab stop per group, arrow keys move (and select for radios, segments, tabs, chip groups), RTL-aware |
| `CamoHideOnScroll` | a `ValueNotifier<bool>` over a `ScrollController` for hide-on-scroll bars and FABs (ADR-30) |
| `CamoClickable` | public: `CamoBehavior` + the **active skin's** feedback + the touch target for an app's own tappable rows |
| `CamoErrorSemantics` | wraps a field with `Semantics(validationResult: …)` and announces new errors via `SemanticsService.announce` |
