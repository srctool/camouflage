# Carbon Skin

## Concept {#concept}

:::info[Milestone: M14, in v0.1 (ADR-40)]

Documented first (ADR-22); ADR-40 puts it in v0.1 as the last of the five skins. It is built whole in one pass after Minimal, Fluent, Material and Cupertino (the M12 ruling: `CamoSkin` has no defaults, so a partial skin can't compile).

:::

### 1. Why

`CarbonSkin` renders Camouflage in **IBM Carbon**'s dialect: **square corners**, flat layered surfaces, a strong grid, productive density, and a bold blue interactive color. It suits enterprise, data-heavy and desktop tools. It stresses the contract in two ways:
- **text fields with a bottom border only** (a different anatomy);
- **layers instead of elevation**, where depth is a different gray per nesting level.

### 2. Shape

```mermaid
flowchart TB
    CB["carbonSkin(theme family = White, G10, G90 or G100)"] --> Lay["Layered surface: no shadows (except overlays), each nested layer one gray step"]
    CB --> Fb["Carbon feedback: hover/active background tokens, inset focus border"]
    CB --> Rs["52 renderers with square corners"]
```

**Surface treatment: `Layered`.** Surfaces use **layer tokens** (`layer-01` … `layer-03`), which map to Camouflage's surface levels. There are no shadows, except for overlays (dialogs and menus get Carbon's single overlay shadow).

**Interaction feedback: `CarbonStates`.** Background swaps to `…-hover` / `…-active` tokens. Focus is a **2 px inset focus border** (`focus` color), so it never changes the layout.

### 3. API

```kotlin
fun carbonSkin(): CamoSkin
fun carbonTheme(family: CarbonThemeFamily = White, fontFamily: FontFamily? = null): CamoTheme   // White | G10 (light) · G90 | G100 (dark)
```

**Starter theme:**
- Carbon's four themes map to roles: `background` → `surface`, `layer-01..03` → `surfaceContainerLow..High`, `text-primary/secondary` → `onSurface`/`onSurfaceVariant`, `border-strong/subtle` → `outline`/`outlineVariant`, `interactive`/`button-primary` → `primary` (blue 60), `support-error/success/warning/info` → the status families.
- Typography: **IBM Plex Sans** for the authentic look, **added by the app** (skins never bundle fonts): `carbonTheme(fontFamily = IbmPlexSans)`, falling back to the platform font, with Carbon's type sets mapped to the 15 roles (heading-07 54 → displayLarge … body-compact-01 14 → bodyMedium, label-01 12 → labelMedium, helper-text-01 12 → bodySmall).
- **Shapes: all 0**, except `full` for toggles and tags.
- Values come from Carbon's published tokens at implementation time.

#### 3.3 Carbon under ADR-42 (materials rule)

Carbon has no materials: no blur, no glass, no shader. `Layered` is opaque everywhere, so the skin reads no `CamoCapabilities` (like Material) and needs no fallback chain. The only things that vary by environment are the input kind (a touch device keeps the 48 targets; a pointer may use the 40 productive heights through `CamoDensity`) and the platform font.

#### 3.4 Chart preset

Charts reach skins through the preset registered for `skin.name == "carbon"` ([Chart Frame](/components/charts/chart-frame)); like the others it ships in the charts package. Proposed values, from Carbon Charts' defaults (square, flat, dashed grid):

| `ChartStyle` field | Carbon | Why |
|---|---|---|
| `lineWidth` | 1.5 | Carbon Charts' thin line |
| `markerSize` | 6 | a point of radius 3 |
| `areaOpacity` | 0.3 | a flat fill under the line |
| `barRadius` | 0 | square, like the whole system |
| `barGap` | 1 | bars nearly touch |
| `gridDashed` | true | Carbon draws dashed grid lines |
| `sliceGap` | 1 | a hairline between slices |
| `donutThickness` | 0.35 | a ring thinner than Cupertino's |

The palette stays the theme's (Carbon's categorical palette is a brand choice, not a preset); the tooltip is a square `layer-02` box with a 1 px border.

#### 3.5 Density (M16, srctool/camouflage#70)

Carbon draws every control at 48 today (the "large" size). Carbon's own size tokens are `xs` 24, `sm` 32, `md` 40 and `lg` 48, and desktop apps live at 32 and 40. Without a density option an app overrides every component theme, which is what Fluent's `density` already avoids.

| Control | `xs` 24 | `sm` 32 | `md` 40 | `lg` 48 (today) |
|---|---|---|---|---|
| Button, icon button | 24 (`bodyCompact01`, 12) | 32 | 40 | 48 |
| Text field, search, select, number input | 24 | 32 | 40 | 48 (the field stays 40 today; see the callout) |
| Menu item, list row, tree row | 24 | 32 | 40 | 48 |
| Data table row | 24 | 32 | 40 | 48 |
| Tab, toolbar action | 24 | 32 | 40 | 48 |

Paddings, icon sizes (16 at `xs` and `sm`, 20 at `md`, 24 at `lg`) and the type size follow the size: Carbon's `body-compact-01` (14) at `sm` and above, 12 at `xs`. Heights are minimums, so 200% text still grows a control (the rule every component follows).

**How the skin follows the input.** `carbonTheme(density = null)` follows `CamoEnvironment.input` (ADR-41), the same rule as `fluentTheme(density)`: a pointer gets `md`, fingers get `lg`. An explicit value wins. The 48 touch target is never reduced: a 24 control with touch input still has a 48 hit area (`minimumTouchTarget` on Kotlin, `CamoTouchTarget` on Flutter), so `xs` costs nothing in accessibility.

### 4. Build steps

1. The `Layered` surface, `CarbonStates` feedback, and the inset focus border.
2. `carbonTheme` for the four families, with a `fontFamily` parameter (the sample app adds IBM Plex Sans).
3. The renderers. Bottom-border text fields and full-width modal button rows are the structural tests. The M9 to M11 ones are included, and the `"carbon"` chart preset (§3.4).
4. The screenshot matrix (White and G100 at least; G10 and G90 in the theme test), plus a manual comparison with Carbon's own components.

### 5. Edge cases

| Case | Decided behavior |
|---|---|
| **Layer nesting** | Carbon's rule: a component on `layer-01` uses `layer-02` for its own fill. Camouflage's `SurfaceLevel` handles this, and nested surfaces step up one level. |
| Square corners vs `shapes` tokens | The Carbon theme sets all shape roles to 0. A brand can still round them, and it's no longer strict Carbon. |
| The dark header in light themes | A Carbon convention: `TopBarTheme.colors` defaults to gray 100 in every family. |
| A material requested (a `Surface` marked blur) | Layered ignores it: every level is an opaque layer token. |
| Contract gaps found | Record them as ADRs and add them to core (e.g. a content switcher with an inverse selected fill). |
| Touch devices | Carbon is desktop-first. The 48 touch targets still apply (the component guarantees them). |

## Implementation {#implementation}

### 1. Why {#kotlin-1-why}

`:camouflage-skin-carbon` implements every renderer in IBM Carbon's dialect using **only Compose foundation** plus `camouflage-core`'s public API. It is the skin with the plainest surface (no shadows, no materials) and the most structural differences in inputs: a text field with a bottom border only, a button whose label starts at the left and whose icon sits at the end, square everything.

### 3. API {#kotlin-3-api}

```kotlin
public val CarbonSkin: CamoSkin = carbonSkin()
public fun carbonSkin(): CamoSkin
public enum class CarbonThemeFamily { White, G10, G90, G100 }
public fun carbonTheme(family: CarbonThemeFamily = White, fontFamily: FontFamily? = null): CamoTheme
public val carbonLight: CamoTheme   // White
public val carbonDark: CamoTheme    // G100
```

- **`Layered`**: opaque fills only. A level maps to a layer token; a surface nested in a surface of the same level steps up one (`SurfaceLevel`). Only overlays (dialog, menu, popover, side sheet when modal) get the single overlay shadow.
- **`CarbonStates`**: a hover or pressed state swaps the fill to the `…-hover` / `…-active` token (an `IndicationNodeFactory` drawing the token over the content); focus is a 2 px inset border in `focus`, drawn inside the bounds so layout never moves; disabled uses `…-disabled` tokens. No ripple, no opacity change.
- **Theme**: `carbonTheme` maps the four families' published tokens to roles (base note §3), the shapes are all 0 except `full`, the motion is Carbon's productive/expressive curves, and the type set is mapped to the 15 roles. The font is not bundled (ADR-33): the sample adds IBM Plex Sans through `fontFamily`.
- **Pinned literals**: like Material and Cupertino, a snapshot test pins the token values (Carbon's own contrast pairs are AA, so the theme test asserts every foreground/background pair passes).
- **Chart preset**: `"carbon"` in `camouflage-charts` (values in the base note §3.4).

### 4. Build steps {#kotlin-4-build-steps}

M14 is built in one pass (the M12 ruling), then reviewed as a whole; the task cards close together.

1. Copy Minimal's module as the starting point, then `Layered`, `CarbonStates`, the inset focus border.

4. The M9 to M11 renderers and the `"carbon"` chart preset.
5. The sample switcher entry (Carbon with a family choice on the theme page), goldens (White, G100, brand), `assertRendererAppliesBehavior` on every clickable renderer, the no-literals test.

### 5. Edge cases {#kotlin-5-edge-cases}

| Case | Decided behavior |
|---|---|
| Nested surface | Steps up one layer token (`layer-01` to `layer-02` to `layer-03`); at `layer-03` it stays. |
| A brand that rounds the shapes | Allowed, no longer strict Carbon. |
| The header in a light family | Gray 100 by default (`TopBarTheme.colors`). |
| Focus on a field with a bottom border | The 2 px inset border goes around the whole field, not only the bottom edge. |
| Carbon on mobile | Allowed. The 48 targets hold; Carbon's 40 productive height applies only when the density is Compact. |

:::info[M16 start (2026-11-11): density (Kotlin)]

- **Theme:** `carbonTheme(family, accent, fontFamily, density: CarbonDensity? = null)`. The enum is `CarbonDensity { Xs, Sm, Md, Lg }`. The value is stored in a `CarbonTokens(density)` token set (`theme.tokens<CarbonTokens>()`), and `null` adapts through `theme.adapt { env -> ... }` (as Fluent does): `Pointer` → `Md`, `Touch` → `Lg`.
- **Renderers:** each renderer's `defaults(theme)` reads `theme.tokens<CarbonTokens>()?.density ?: Lg` through one internal `CarbonSizes` table (height, padding, icon size, text style), replacing the `48.dp` and `40.dp` literals in `CarbonActions`, `CarbonInputs`, `CarbonLists`, `CarbonGroups`, `CarbonNavigation` and `CarbonNavigationChrome`.
- **Touch target:** unchanged; `minimumTouchTarget()` keeps 48 × 48 around a 24 control.
- **Tests:** a size table test per density (button, field, row heights), the `null` adaptation for `Pointer` and `Touch`, an explicit value winning, the 48 target holding at `Xs` with touch, and goldens per density in White and G100.
- **Done when:** a Carbon screen at `Xs` has 24 buttons, fields and rows with no component-theme override, on Kotlin.
